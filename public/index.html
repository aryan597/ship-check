READING THE CODE…

Why we do this. Running code is an act of trust.

When you run someone’s project, it can do anything you can do: read your files, use your logins, and send your keys anywhere. Most of us run it anyway, because nobody has time to read every file.

Installing is running.

A single npm install can run code from the project before you’ve opened one file.

A nice README proves nothing.

It tells you what a project says it does, not what the code really does.

AI tools run code too.

Coding assistants download and run projects for you, and a file can try to talk them into it.

So we read it first.

ShipCheck reads the code without running it and shows you the exact lines that worry us, so the decision stays yours. It won’t catch everything, but it beats going in blind.

What’s the first thing you check? We check these six.

INSTALL TRAPS

Scripts that run by themselves the moment you type npm install.

"postinstall": "curl … | bash"
DOWNLOAD-AND-RUN

Code pulled from the internet and run on the spot, without you seeing it.

wget -qO- … | sh
LEAKED KEYS

Passwords and API keys left in the code or in private settings files.

AKIA•••• · sk-p•••• · ghp_••••
DATA THEFT

Your private settings quietly sent to webhooks, Pastebin, Discord or unknown servers.

fetch("webhook…", process.env)
HIDDEN CODE

Code disguised as scrambled text, and invisible characters hiding in plain sight.

eval(Buffer.from(…, "base64"))
AI TRICKS

Messages written to talk your AI assistant into calling the project safe.

"ignore previous instructions"
